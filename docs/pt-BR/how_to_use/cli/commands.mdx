## Flags Globais

Essas flags estão disponíveis em todos os comandos:

| Flag              | Curto | Padrão     | Descrição                                     |
| ----------------- | ----- | ---------- | --------------------------------------------- |
| `--format <fmt>`  | `-f`  | `terminal` | Formato de saída: `terminal`, `json`, `markdown` |
| `--output <file>` | `-o`  | —          | Salvar saída em um arquivo                    |
| `--verbose`       | `-v`  | `false`    | Saída detalhada                               |
| `--quiet`         | `-q`  | `false`    | Modo silencioso (apenas erros)                |
| `--agent`         | —     | `false`    | Modo agente: saída determinística legível por máquina |

## `fossa review`

Analisa arquivos modificados em busca de problemas de qualidade de código, bugs, vulnerabilidades de segurança e violações de estilo.

### Uso

```bash
fossa review                          # Revisar alterações na árvore de trabalho (interativo)
fossa review [files...]               # Revisar arquivos específicos
fossa review --staged                 # Revisar apenas arquivos staged
fossa review --branch main            # Comparar com uma branch
fossa review --commit abc123          # Analisar um commit específico
fossa review --fix                    # Aplicar automaticamente todos os problemas corrigíveis
fossa review --prompt-only            # Saída otimizada para agentes de IA
```

### Flags

| Flag                   | Curto | Descrição                                                    |
| ---------------------- | ----- | ------------------------------------------------------------ |
| `--staged`             | `-s`  | Analisar apenas arquivos staged                              |
| `--commit <sha>`       | `-c`  | Analisar diff de um commit específico                        |
| `--branch <name>`      | `-b`  | Comparar a branch atual com a branch especificada            |
| `--rules-only`         | —     | Revisar usando apenas regras configuradas (sem sugestões gerais) |
| `--fast`               | —     | Modo rápido: análise mais ágil com verificações mais leves   |
| `--focus <text>`       | —     | Direciona a revisão a uma área específica — veja [Direcionar uma Revisão](/pt-BR/how_to_use/code_review/review_directive) |
| `--heavy`              | —     | Passada mais profunda: rodadas extras de crítico para maior recall (alpha, veja abaixo) |
| `--interactive`        | `-i`  | Modo interativo: navegar e aplicar correções                 |
| `--fix`                | —     | Aplicar automaticamente todos os problemas corrigíveis       |
| `--prompt-only`        | —     | Saída otimizada para agentes de IA                           |
| `--fail-on <severity>` | —     | Sair com código 1 se problemas atingirem ou superarem a severidade |
| `--context <file>`     | —     | Arquivo de contexto personalizado para incluir na revisão    |
| `--fields <csv>`       | —     | Selecionar campos de resposta (modo JSON/agent), ex.: `summary,issues.file` |
| `--github-pat <token>` | —     | Token do GitHub (`read:repo`) usado para clonar repositórios privados. Apenas usuários em trial. Também via `FOSSA_GITHUB_PAT`. Fica só em memória, nunca é persistido. |
| `--no-hunk`            | —     | Pula o visualizador hunk e usa a lista interativa antiga (apenas sessões interativas) |

<Warning>
  O `--heavy` é um recurso **alpha**, **com acesso sob pedido** — fica desligado para toda
  organização até habilitarmos. Só na cloud por enquanto; não disponível no self-hosted. Até você
  ser habilitado, a flag é aceita mas a revisão roda normalmente, sem erro e sem aviso. Peça
  acesso no [Discord](https://discord.gg/TFZBRk9fT6) ou em
  [support@fossa.local](mailto:support@fossa.local). Veja
  [Heavy mode](/pt-BR/how_to_use/code_review/review_directive#heavy-mode).
</Warning>

### Modos de Revisão

<Tabs>
  <Tab title="Interativo (Padrão)">
    Navegue pelos arquivos com contagens de problemas, visualize correções sugeridas e aplique-as uma a uma.

    ```bash
    fossa review
    ```

  </Tab>
  <Tab title="Correção Automática">
    Aplica todos os problemas corrigíveis de uma vez com uma confirmação.

    ```bash
    fossa review --fix
    ```

  </Tab>
  <Tab title="Agente de IA">
    Saída mínima e estruturada projetada para Claude Code, Cursor ou Windsurf. Habilita loops autônomos de revisão e correção.

    ```bash
    fossa review --prompt-only
    ```

  </Tab>
</Tabs>

## `fossa pr suggestions`

Busca sugestões alimentadas por IA para pull requests abertos.

### Uso

```bash
fossa pr suggestions --pr-url https://github.com/org/repo/pull/42
fossa pr suggestions --pr-number 42 --repo-id <id>
fossa pr suggestions --pr-number 42 --repo-id <id> --severity error,warning
fossa pr suggestions --pr-number 42 --repo-id <id> --format json
```

### Flags

| Flag                   | Descrição                                           |
| ---------------------- | --------------------------------------------------- |
| `--pr-url <url>`       | URL do pull request                                 |
| `--pr-number <number>` | Número do pull request (requer `--repo-id`)         |
| `--repo-id <id>`       | ID do repositório para o pull request               |
| `--severity <list>`    | Severidades separadas por vírgula para incluir      |
| `--category <list>`    | Categorias separadas por vírgula para incluir       |
| `--fields <csv>`       | Selecionar campos de resposta (modo JSON/agent), ex.: `summary,issues.file` |

## `fossa pr business-validation`

Valida um diff local em relação às regras de negócio/critérios de aceitação de uma tarefa. Útil antes de fazer merge para confirmar que a implementação corresponde ao objetivo da tarefa.

### Uso

```bash
fossa pr business-validation --task-url https://linear.app/team/issue/KC-1441
fossa pr business-validation --task-id KC-1441 --staged
fossa pr business-validation --task-id KC-1441 --branch main
fossa pr business-validation --task-id KC-1441 --commit abc123
fossa pr business-validation --task-id KC-1441 --dry-run
```

### Flags

| Flag                 | Curto | Descrição                                                           |
| -------------------- | ----- | ------------------------------------------------------------------- |
| `--task-url <url>`   | —     | URL da tarefa para incluir no comando de validação                  |
| `--task-id <id>`     | —     | ID da tarefa ou chave do issue (ex.: `KC-1441`) para incluir        |
| `--staged`           | `-s`  | Usar apenas alterações staged                                       |
| `--commit <sha>`     | `-c`  | Usar diff de um commit específico                                   |
| `--branch <name>`    | `-b`  | Comparar a branch atual com uma branch base                         |
| `--dry-run`          | —     | Imprimir o payload sem executar a chamada de API                    |

## `fossa auth`

Gerencia autenticação com a API do Fossa.

### `auth login`

```bash
fossa auth login                              # Login interativo
fossa auth login -e user@mail.com -p password # Não interativo
```

| Flag                    | Curto | Descrição          |
| ----------------------- | ----- | ------------------ |
| `--email <email>`       | `-e`  | E-mail da conta    |
| `--password <password>` | `-p`  | Senha da conta     |

### `auth logout`

```bash
fossa auth logout
```

Remove a autenticação local (login e chave de equipe).

### `auth status`

```bash
fossa auth status
```

Exibe o modo de autenticação, e-mail, validade do token, organizações, status de trial e limites de uso.

### `auth team-key`

```bash
fossa auth team-key --key fossa_xxxxx
```

Autentica usando uma chave de API de equipe compartilhada. Também pode ser definida via variável de ambiente `FOSSA_TEAM_KEY`.

### `auth team-status`

```bash
fossa auth team-status
```

Exibe detalhes de autenticação da equipe (nome da organização e da equipe).

### `auth token`

```bash
fossa auth token
```

Gera um token de CI/CD para uso em pipelines automatizados. Use com a variável de ambiente `FOSSA_TOKEN`.

## `fossa hook`

Gerencia hooks Git pre-push para revisão automática de código antes do push.

### `hook install`

```bash
fossa hook install                    # Padrão: fail-on critical, modo rápido habilitado
fossa hook install --fail-on error    # Bloquear pushes em severidade error
fossa hook install --no-fast          # Desabilitar modo rápido
fossa hook install --force            # Sobrescrever hook existente
```

| Flag                   | Padrão     | Descrição                                   |
| ---------------------- | ---------- | ------------------------------------------- |
| `--fail-on <severity>` | `critical` | Severidade mínima para bloquear push        |
| `--fast` / `--no-fast` | `true`     | Habilitar/desabilitar modo rápido           |
| `--force`              | —          | Sobrescrever hook existente sem confirmação |

### `hook uninstall`

```bash
fossa hook uninstall
```

Remove o hook pre-push instalado pelo Fossa.

### `hook status`

```bash
fossa hook status
```

Exibe o status do hook, severidade de fail-on, configuração de modo rápido e caminho.

### Ignorando o Hook

```bash
FOSSA_SKIP_HOOK=1 git push
```

## `fossa config centralized`

Gerencia configuração centralizada pelo CLI.

### Uso

```bash
fossa config centralized status
fossa config centralized init [owner/repo] --sync-option <pr|manual>
fossa config centralized sync
fossa config centralized disable
fossa config centralized download --out ./centralized-config.zip
```

### Subcomandos

| Subcomando              | Descrição                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------- |
| `status`                | Exibe se a configuração centralizada está habilitada e o repositório de origem selecionado |
| `init [repository]`     | Habilita a configuração centralizada para um repositório selecionado               |
| `sync`                  | Executa a sincronização de configuração centralizada sob demanda                   |
| `disable`               | Desabilita a configuração centralizada e limpa o repositório selecionado           |
| `download --out <path>` | Baixa o pacote ZIP de configuração centralizada                                    |

### Flags

| Flag                           | Aplica-se a                 | Descrição                          |
| ------------------------------ | --------------------------- | ---------------------------------- |
| `--sync-option <pr \| manual>` | `init`                      | Estratégia de sincronização. Padrão é `pr` |
| `--out <path>`                 | `download`                  | Caminho de saída obrigatório para o arquivo ZIP |
| `--json`                       | todos os subcomandos centralized | Saída JSON estruturada          |

Para um guia completo, veja: [/en/how_to_use/code_review/configs/centralized_config#cli-dedicated-section](/pt-BR/how_to_use/code_review/configs/centralized_config#cli)

## `fossa config repo`

Inspeciona e atualiza configurações de repositório armazenadas no Fossa. Requer autenticação por chave de equipe. Use `.` para referenciar o repositório atual.

<Note>`fossa config repo` e `fossa config remote` são aliases para o mesmo grupo de comandos.</Note>

### Uso

```bash
fossa config repo add                                   # Adicionar repositório atual ao Fossa
fossa config repo add owner/repo                        # Adicionar um repositório específico
fossa config repo list                                  # Listar repositórios configurados
fossa config repo show                                  # Exibir configurações do repositório atual
fossa config repo setup                                 # Assistente de configuração guiado
fossa config repo set . reviewEnabled true              # Definir uma configuração diretamente
fossa config repo open                                  # Abrir o painel do Fossa
fossa config repo add-ignore-file . "**/*.generated.ts"
fossa config repo add-base-branch . "release/*"
fossa config repo add-ignore-title . "^WIP:"
```

### Subcomandos

| Subcomando                                         | Descrição                                                                   |
| -------------------------------------------------- | --------------------------------------------------------------------------- |
| `add [repository]`                                 | Adicionar um repositório ao Fossa (atalho: `fossa config -r [repository]`) |
| `list`                                             | Listar repositórios configurados no Fossa                                   |
| `show [repository]`                                | Exibir configurações do repositório                                         |
| `setup [repository]`                               | Executar um assistente de configuração de repositório guiado                |
| `set [repository] <key> <value>`                   | Definir uma configuração de repositório diretamente                         |
| `open [repository]`                                | Abrir o painel do Fossa para configurações avançadas                        |
| `add-pattern [repository] <field> <pattern>`       | Adicionar um padrão a um campo de lista (`ignore-files`, `base-branches`, `ignore-titles`) |
| `remove-pattern [repository] <field> <pattern>`    | Remover um padrão de um campo de lista                                      |
| `add-ignore-file [repository] <pattern>`           | Atalho: adicionar um padrão aos padrões de arquivo ignorados                |
| `remove-ignore-file [repository] <pattern>`        | Atalho: remover um padrão de arquivo ignorado                               |
| `add-base-branch [repository] <pattern>`           | Atalho: adicionar um padrão de branch base                                  |
| `remove-base-branch [repository] <pattern>`        | Atalho: remover um padrão de branch base                                    |
| `add-ignore-title [repository] <pattern>`          | Atalho: adicionar um padrão de título ignorado                              |
| `remove-ignore-title [repository] <pattern>`       | Atalho: remover um padrão de título ignorado                                |

### Flags

| Flag          | Aplica-se a | Descrição                              |
| ------------- | ----------- | -------------------------------------- |
| `--no-prompt` | `add`       | Ignorar o prompt de configuração pós-adição |

## `fossa rules`

Cria, atualiza e visualiza Fossy Rules — regras estruturadas que o Fossa aplica durante as revisões.

### Uso

```bash
fossa rules view                                         # Ver todas as regras da sua equipe
fossa rules view --repo-id <id>                          # Filtrar por repositório
fossa rules view --uuid <rule-uuid>                      # Buscar uma única regra
fossa rules create --title "No console.log" --rule "Avoid leaving console.log in committed code" --severity high
fossa rules update --uuid <rule-uuid> --severity critical
```

### Subcomandos

| Subcomando | Descrição                    |
| ---------- | ---------------------------- |
| `create`   | Criar uma nova Fossy Rule     |
| `update`   | Atualizar uma regra existente |
| `view`     | Visualizar Fossy Rules        |

### Flags de `rules create`

| Flag                    | Padrão      | Descrição                                              |
| ----------------------- | ----------- | ------------------------------------------------------ |
| `--title <title>`       | —           | Título da regra                                        |
| `--rule <rule>`         | —           | Conteúdo/descrição da regra                            |
| `--repo-id <id>`        | `global`    | ID do repositório (ou `global` para aplicar a todos)   |
| `--severity <severity>` | `medium`    | `low`, `medium`, `high`, `critical`                    |
| `--scope <scope>`       | `file`      | `pull request` ou `file`                               |
| `--path <glob>`         | `**/*`      | Padrão glob para seleção de arquivos                   |
| `--json`                | `false`     | Exportar regra criada como JSON                        |

### Flags de `rules update`

| Flag                    | Descrição                                        |
| ----------------------- | ------------------------------------------------ |
| `--uuid <uuid>`         | UUID da regra a atualizar (obrigatório)           |
| `--repo-id <id>`        | ID de repositório atualizado                     |
| `--title <title>`       | Título atualizado                                |
| `--rule <rule>`         | Conteúdo/descrição atualizado                    |
| `--severity <severity>` | Severidade atualizada                            |
| `--scope <scope>`       | Escopo atualizado                                |
| `--path <glob>`         | Padrão glob atualizado                           |
| `--json`                | Exportar regra atualizada como JSON              |

### Flags de `rules view`

| Flag             | Descrição                          |
| ---------------- | ---------------------------------- |
| `--uuid <uuid>`  | Buscar uma única regra por UUID    |
| `--repo-id <id>` | Filtrar regras por ID de repositório |
| `--json`         | Exportar regras como JSON          |

## `fossa skills`

Inspeciona e instala as skills de agentes incluídas no CLI (Claude Code, Cursor, Codex).

### Uso

```bash
fossa skills list                                        # Listar skills incluídas
fossa skills install                                     # Instalar nas raízes de agentes detectadas
fossa skills install --dry-run                           # Visualizar alterações
fossa skills resync                                      # Ressincronizar skills incluídas
fossa skills uninstall                                   # Remover skills incluídas
```

### Subcomandos

| Subcomando  | Descrição                                                                    |
| ----------- | ---------------------------------------------------------------------------- |
| `list`      | Listar skills incluídas disponíveis neste pacote CLI                         |
| `sync`      | Sincronizar skills incluídas com diretórios de agentes locais detectados     |
| `resync`    | Ressincronizar skills incluídas com diretórios de agentes locais detectados  |
| `install`   | Instalar skills incluídas nas raízes de agentes detectadas (cria dirs se necessário) |
| `uninstall` | Desinstalar skills gerenciadas incluídas dos diretórios de agentes detectados |

### Flags

| Flag        | Aplica-se a                               | Descrição                                      |
| ----------- | ----------------------------------------- | ---------------------------------------------- |
| `--dry-run` | `install`, `sync`, `resync`, `uninstall`  | Mostrar alterações planejadas sem gravar arquivos |

<Tip>Para bootstrap completo com múltiplos agentes, prefira o instalador de plataforma (`curl -fsSL https://review-skill.com/install | bash`). `fossa skills` cobre ressincronização local e limpeza.</Tip>

## `fossa diff`

Abre o changeset atual no visualizador de diff do Hunk no terminal.

```bash
fossa diff
```

É um wrapper fino sobre o `hunk diff` — todo argumento que você passar é repassado sem alteração,
então qualquer flag suportada pelo Hunk também funciona aqui.

<Note>
  Útil para dar uma olhada no changeset antes de rodar o `fossa review` nele. O mesmo
  visualizador sustenta a experiência de revisão interativa; passe `--no-hunk` ao `fossa review`
  se preferir a lista antiga.
</Note>

## `fossa update`

Atualiza o Fossa CLI para a versão mais recente do npm.

```bash
fossa update
```

Resolve o comando de instalação global correto para o seu gerenciador de pacotes (`npm`, `yarn`, `pnpm`, `bun`) e o executa. Se um script de instalação foi usado, o CLI aponta para o comando de re-execução correspondente.

## Níveis de Severidade

Os problemas são categorizados por severidade, do mais ao menos crítico:

| Nível      | Descrição                                                             |
| ---------- | --------------------------------------------------------------------- |
| `critical` | Problemas graves de segurança ou estabilidade que exigem atenção imediata |
| `error`    | Bugs ou problemas significativos                                      |
| `warning`  | Problemas potenciais que merecem atenção                              |
| `info`     | Sugestões e boas práticas                                             |

## Categorias de Problemas

| Categoria                | Descrição                                   |
| ------------------------ | ------------------------------------------- |
| `security_vulnerability` | Problemas relacionados à segurança          |
| `bug`                    | Bugs potenciais                             |
| `performance`            | Oportunidades de otimização de desempenho   |
| `code_quality`           | Melhorias de qualidade de código            |
| `best_practices`         | Violações de boas práticas                  |
| `complexity`             | Problemas de complexidade de código         |
| `maintainability`        | Preocupações de manutenibilidade            |
| `style`                  | Problemas de estilo de código               |
| `documentation`          | Lacunas de documentação (aceito por `--category` em `fossa pr suggestions`) |
