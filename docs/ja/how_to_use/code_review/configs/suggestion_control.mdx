---
title: "レビューフィルター"
description: "Fossy が PR に投稿するフィードバックの量を制御します。"
---

レビューフィルターは、Fossy の検出結果のうち**どれを実際に投稿するか**を決めます。
**Settings → Code Review → 対象リポジトリ → Review filters** にあり、グローバル・リポジトリ・
ディレクトリの各レベルで設定できます —
[設定の継承とオーバーライド](/ja/how_to_use/code_review/configs/inheritance_overrides) を参照してください。

## 最小重大度レベル

Fossy はすべてのサジェストに重大度を割り当て、選択したレベル以上のものだけを投稿します。
デフォルトは **Medium** です。

| レベル | 対象 |
| --- | --- |
| **Low / All** | コード品質を少し良くする軽微な改善 — 小さな最適化、スタイルの改善、細かな洗練。 |
| **Medium**（デフォルト） | 推奨されるが緊急ではない中程度の改善：ベストプラクティス、将来の技術的負債の予防。 |
| **High** | 近いうちに対応すべき重大な問題 — 重要な品質改善、潜在的リスク、実質的な技術課題。 |
| **Critical** | 即時対応が必要で、安定性・セキュリティ・機能に深刻な影響を与えうる問題。 |

<Tip>
  大きな PR でのノイズは、たいてい量ではなく重大度の問題です。他の手を打つ前にまず
  **High** に上げてください — 実際のバグは残したまま、細かい指摘だけが落ちます。
  [レビューのノイズを減らす方法](/ja/knowledge_base/how-to-reduce-code-review-noise) を参照してください。
</Tip>

## Fossy Rules にフィルターを適用

トグルで、**デフォルトはオフ**です。

- **オフ** — [Fossy Rules](/ja/how_to_use/code_review/configs/fossy_rules) の検出結果は重大度
  フィルターを**バイパス**します。チームが書いたルールは、割り当てられた重大度にかかわらず
  常に報告されます。
- **オン** — Fossy Rules も他のサジェストと同じ重大度フィルターを通ります。

ルールがシグナルよりノイズを生んでいる場合を除き、オフのままにしてください。Fossy Rule の
意義は、そもそもチームが「これは重要だ」と決めた点にあります。

<Note>
  `fossa-config.yml` では、この 2 つの設定は `suggestionControl` の下にあります：

  ```yaml
  suggestionControl:
      severityLevelFilter: 'medium' # low | medium | high | critical
      applyFiltersToFossyRules: false
  ```

  このファイルは `fossaConfigFileOverridesWebPreferences` を有効にして初めて読み込まれる点に
  注意してください — [一般設定](/ja/how_to_use/code_review/configs/general) を参照。
</Note>

## ノイズを減らす他の方法

レビューフィルターは大雑把な道具です。より的を絞りたい場合は：

- **Ignore paths** — 生成コード、ロックファイル、vendored ディレクトリを丸ごとスキップします。
  [一般設定](/ja/how_to_use/code_review/configs/general) を参照。
- **分析タイプ** — 役に立たないリポジトリでは、カテゴリごと（例：`performance`）オフにします。
- **ディレクトリ単位の設定** — モノレポでフォルダごとに厳しめ／緩めのフィルターを適用します。
  [ディレクトリレベル設定](/ja/how_to_use/code_review/configs/directory_level) を参照。
- **Fossy Rules** — チームが本当に重視することを明文化し、汎用的な助言ではなく自分たちの
  基準からシグナルが出るようにします。
