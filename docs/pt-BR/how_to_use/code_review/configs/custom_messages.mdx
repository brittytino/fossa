## Visão Geral

Personalize as mensagens que Fossy envia no início e no fim das revisões de código. Este recurso permite personalizar o estilo de comunicação e adicionar contexto específico ou instruções para sua equipe.

## Comportamento Padrão

Quando você não personalizou nenhuma mensagem, Fossy funciona da seguinte forma:

1. **Mensagem Inicial**: Fossy envia uma mensagem padrão de início de revisão
2. **Sugestões**: Fossy fornece todas as sugestões de code review
3. **Mensagem Final**: Fossy atualiza a mensagem inicial com um resumo da revisão

## Comportamento com Mensagens Personalizadas

Assim que você editar a mensagem de início ou fim de revisão pela primeira vez, o comportamento de Fossy muda para:

1. **Mensagem Inicial**: Fossy envia sua mensagem personalizada de início de revisão
2. **Sugestões**: Fossy fornece todas as sugestões de code review
3. **Mensagem Final**: Fossy envia sua mensagem personalizada de fim de revisão (sem atualizar a mensagem inicial)

Isso cria uma linha do tempo completa: **Mensagem Inicial → Sugestões → Mensagem Final**

## Opções de Configuração de Mensagens

### Comportamento da Mensagem

Use o menu suspenso **Comportamento da mensagem** para decidir quando Fossy deve postar suas mensagens
de início e fim personalizadas:

- **Importante:** As mensagens são enviadas apenas quando uma revisão de fato é executada.  
  Se a sua cadência de revisão for **Manual**, as mensagens são postadas somente quando alguém executa `@fossy start-review`.

- **A cada push**: Fossy posta a mensagem de início quando o pull request é aberto e
  repete o par início/fim após cada novo push **que aciona uma revisão**.
  Isso acontece automaticamente apenas quando a cadência é **Automática** ou **Auto-pause**.
- **Somente quando aberto**: Fossy envia as mensagens de início e fim apenas uma vez, logo
  após a primeira execução da revisão. Se a cadência for **Manual**, a primeira execução
  é quando você chama `@fossy start-review`. Pushes futuros apenas adicionam sugestões
  de revisão mais a reação usual para que os autores saibam que a revisão foi reexecutada.
- **Desativado**: As mensagens personalizadas estão desabilitadas. Fossy ainda executa a revisão e posta
  sugestões, mas nenhuma mensagem de início ou fim é enviada.

Quando o comportamento é `A cada push` ou `Somente quando aberto`, Fossy usa os
templates que você preencheu. Se você personalizar apenas a mensagem de início, apenas essa
mensagem é enviada; o mesmo vale para a mensagem de fim. Isso mantém a linha do tempo familiar de
**Mensagem Inicial → Sugestões → Mensagem Final** sempre que o comportamento permite
que as mensagens sejam postadas.

**Exemplo (cadência Manual)**  
PR aberto → nenhuma mensagem ainda  
`@fossy start-review` → mensagem de início → sugestões → mensagem de fim

## Contexto Dinâmico

Você pode enriquecer suas mensagens personalizadas com contexto dinâmico usando o botão **Adicionar Contexto**. Isso permite incluir:

### changedFiles

Um resumo dos arquivos alterados, mostrando adições e exclusões por arquivo. Fornece um detalhamento completo do que foi modificado no pull request.

### changeSummary

Um resumo abrangente de todas as alterações no pull request, dando uma visão geral de todo o escopo das modificações.

### reviewOptions

Um reflexo das configurações de revisão da equipe, mostrando quais tipos de análise estão habilitados ou desabilitados para a revisão.

### reviewCadence

Fornece a política exata de revisão de acompanhamento para que os autores saibam o que acontece após
a primeira revisão automatizada:

- **Automático**: Fossy revisita cada push assim que chega.
- **Auto-pause**: Fossy revisita pushes automaticamente, mas se detectar uma
  "rajada de pushes" (por exemplo, 3 pushes em 15 minutos, com base nos seus
  limites) pausa as revisões de acompanhamento até que você as retome. O contexto de cadência
  inclui os limites de push e tempo para que a equipe saiba quando a pausa pode
  ser acionada.
- **Manual**: Fossy aguarda alguém executar `@fossy start-review` antes de fazer
  outra passagem.

### reviewScope

Mostra qual nível de configuração — global, repositório ou diretório — foi usado para revisar
este pull request, para que os autores saibam quais configurações valeram.

### agentPrompt

<Note>
  **Apenas na mensagem de fim de revisão.** Ela agrupa as sugestões de comentário de linha da
  revisão, que só existem depois que a revisão rodou — por isso não é oferecida na mensagem de
  início.
</Note>

Agrupa todas as sugestões da revisão em um único bloco de prompt para copiar e colar
(renderizado como um **Open Agent Prompt** recolhível). Cole no seu agente de código para
aplicar de uma vez todas as correções da revisão.

<Info>
  Essas variáveis de contexto serão preenchidas automaticamente com os dados reais
  do seu pull request quando Fossy enviar a mensagem.
</Info>

<Note>
  No `fossa-config.yml` esses tokens são escritos com prefixo `@` — `@changedFiles`,
  `@changeSummary`, `@reviewOptions`, `@reviewCadence`, `@reviewScope`, `@agentPrompt` —
  em qualquer posição dentro do `content` da mensagem. O botão **Add Context** insere os
  mesmos tokens pra você na interface web.
</Note>

## Mensagem de erro

Separada do par início/fim, você pode anexar seu próprio texto ao comentário que o Fossy publica
quando uma revisão **falha** — por exemplo quando não há provider BYOK configurado, ou quando o
provider rejeitou a requisição.

- **Off** (padrão) — o Fossy publica a mensagem de erro padrão, sem alteração.
- **Active** — seu texto é anexado abaixo da mensagem de erro padrão.

Use para apontar as pessoas ao responsável certo ou ao runbook, em vez de deixá-las com uma
falha genérica:

```yaml
customMessages:
    errorReviewMessage:
        status: 'active' # off | active
        content: |
            Revisões falhando? Chame o #platform-eng — a chave da API do Fossa é nossa.
```

Deixar `content` vazio mantém a mensagem de erro padrão inalterada.

## Configurações globais

Dois toggles que valem para todo comentário do Fossy, não só para as mensagens customizadas:

| Configuração | Padrão | O que faz |
| --- | --- | --- |
| `hideComments` | `false` | Publica toda mensagem de revisão como comentário oculto/minimizado. Aparece na interface como **Post as hidden comment**. **Apenas GitHub** — o toggle fica escondido nas outras plataformas. |
| `suggestionCopyPrompt` | `true` | Adiciona às sugestões o recurso de copiar como prompt, para você colar num agente de código. **Não disponível no Bitbucket.** |

```yaml
customMessages:
    globalSettings:
        hideComments: false # apenas GitHub
        suggestionCopyPrompt: true # não disponível no Bitbucket
```

<Note>
  Você sempre pode reverter para o comportamento padrão desabilitando ambas as mensagens
